# Calm Feed v0.2 — Slop filter + Analytics

Spec for extending the existing **Calm Feed** browser extension (`ragebait-filter/`). Read the current code first, because some files have been edited since v0.1. Then implement the two features below.

> Working agreement: the scope below has been agreed. If something here turns out to be impractical while implementing (selectors, storage limits, MV3 constraints), stop and discuss the alternative instead of silently changing the design.

---

## 0. Current state (v0.1, for orientation)

Manifest V3. It runs on Chrome, Brave, Edge and Arc, and on Firefox 121+.

| File | Role |
|---|---|
| `manifest.json` | Content scripts on X, Instagram, Facebook, Reddit, YouTube, Threads, Bluesky, LinkedIn. `document_start`. |
| `src/common.js` | `RBF` namespace: `DEFAULTS`, `getSettings/saveSettings` (`chrome.storage.local` key `rbf_settings`), `norm`, `hash` (FNV-1a), `today`. |
| `src/sites.js` | Per-site adapters: `post` selector, `container(el)`, `text(el)`, `author(el)`. |
| `src/heuristics.js` | `RBF_HEUR.score(text, settings)` → `{score, reasons}`. Regex lexicons (EN+DE) for outrage, out-group, engagement bait and rage emoji, plus caps and punctuation, combined into weighted log-odds and squashed with a logistic. |
| `src/content.js` | Pre-hide CSS (`:is(post):not([data-rbf="ok"]) {visibility:hidden}`) and a MutationObserver. Per post: lists, then heuristic, then optional Claude (batched, strict mode with timeout), then `reveal()` or `block()`. Modes: `remove` / `stub`. Hover ⊘ button for flag or mute. |
| `src/background.js` | Claude Messages API call (batched ≤15, JSON array reply), verdict cache (`rbf_cache`, ~4000 entries), few-shot feedback examples (`rbf_examples`), daily stats (`rbf_stats`). |
| `popup.*`, `options.*`, `ui.css` | Popup (toggle, today's count, sensitivity), settings page. |

## 1. Feature A — Slop scorer

### Goal
Hide **generic, formulaic, low-effort text**: LinkedIn-style template posts, AI-reply-bot comments, stock-phrase filler. The scorer judges **style, not authorship**. It does not try to prove a text was AI-written; AI-text detection is unreliable and full of false positives. A human writing formulaic slop gets filtered. A post someone wrote with AI help that has real, specific content should pass.

**Out of scope for v0.2:** images, video, and comment sections other than X replies.

### A1. New file `src/slop.js`
Exports `RBF_SLOP.score(text, settings, ctx)` → `{ score: 0..1, reasons: string[] }`. It has the same contract and the same log-odds + logistic approach as `heuristics.js`, with separate lexicons and weights. `ctx` = `{ site, isReply }`.

Signals (EN + DE; keep every lexicon in one editable block at the top of the file):

1. **Stock phrases**
   - "here's the thing", "here's why", "let that sink in", "read that again", "game[- ]changer", "in today's (fast-paced|digital|ever-evolving) world", "delve", "unlock (your|the) (potential|power)", "let's dive in", "a testament to", "navigate the (complexities|landscape)", "it's important to note", "the bottom line", "buckle up", "here's what I learned", "(10|5|7) lessons", "nobody talks about", "thoughts\?", "agree\?"
   - DE: "hier ist der punkt", "lass das mal sacken", "gamechanger", "in der heutigen schnelllebigen welt", "was ich gelernt habe", "eure meinung\?"
2. **"Not X, it's Y" contrast template.** Includes "It's not about X. It's about Y.", "This isn't X — it's Y", and "Es geht nicht um X, sondern um Y".
3. **Template structure**
   - The first line is a short hook (< 12 words), followed by a blank line.
   - ≥ 3 lines starting with an emoji bullet (✅ 🚀 💡 👉 🔥 📌 ➡️ ✨ 🎯) or with "→".
   - The post ends with a CTA or question ("Thoughts?", "Agree?", "Comment X", "Repost ♻️", "Follow me for more").
   - A trailing hashtag block (≥ 3 hashtags in the last 2 lines).
   - **Broetry:** ≥ 70% of non-empty lines are one sentence, and there are ≥ 6 lines.
4. **Rule of three.** Repeated triads like "faster, smarter, better" or "X, Y, and Z" adjective/verb lists. Count matches of `\b(\w+), (\w+),? and (\w+)\b`, where the words are short and of the same kind. Weak signal.
5. **Em-dashes (density-based, weak alone)**
   - Count `—` and ` – `, where a spaced en-dash is also used as a dash in German and should be treated the same.
   - A rate per 100 words below 1 adds nothing.
   - ≥ 4 in a post under 150 words adds a moderate amount.
   - Dashes count **strongly only in combination** with signals 1–3 (an interaction term, as `outrage + outgroup` works in `heuristics.js`).
   - A single em-dash must never by itself push a post over the threshold.
6. **Bot replies** (`ctx.isReply`, or a short post under 40 words on X)
   - Generic praise opener: "great (insight|point|post|thread)", "this is (so )?(true|spot on|powerful)", "absolutely (agree|love this)", "well said", "couldn't agree more", "what a (great|fantastic)…", "thanks for sharing".
   - Plus a restatement pattern: "this (really )?(highlights|underscores|shows) the importance of".
   - Plus **no specifics**: no numbers, no proper nouns other than a leading @mention, no URLs.
   - Emoji-only or "🔥🔥🔥 / 💯" replies count as bot-ish only when combined with a praise phrase. Plain emoji reactions are fine.
7. **Specificity discount (negative weight)**
   - Numbers with units, dates, code snippets, links, named people or places, first-person concrete details ("I spent 4 hours on a race condition") reduce the score.
   - This is the main guard against false positives on real posts.

Short texts (< 12 chars) score 0. Custom always-hide keywords keep their current behaviour.

### A2. X replies
On X, reply tweets are already `article[data-testid="tweet"]`. Set `isReply` when the post is inside a conversation thread and is not the focal tweet: on `/status/` pages, every article except the first. It is also a reply when the article contains a "Replying to" element. Pass `{site, isReply}` through `sites.js` as an optional `ctx(el)` adapter function. Other sites return `isReply: false` for now.

### A3. Decision logic (`content.js`)
For each post, compute both scores:

```
r = RBF_HEUR.score(text)        // ragebait
s = RBF_SLOP.score(text, ctx)   // slop
```

The order of checks:
1. allow list
2. block list
3. keywords
4. ragebait `r ≥ threshold` → block (filter = `ragebait`)
5. slop `s ≥ slopThreshold` → block (filter = `slop`)
6. LLM, if enabled
7. reveal

The slop checks only apply when `slopEnabled` and `slopSites[site]` are both true. `block()` gets a `filter` argument (`ragebait | slop | keyword | author | manual`). The stub shows it: `Filtered · Slop · em-dash ×5, stock phrases ×2`.

### A4. Claude pass (`background.js`)
- The same batched call returns **both** scores: `[{"i":0,"r":0.12,"s":0.81,"why":"…"}]`.
- Add a short slop definition to the system prompt, mirroring A1. It should cover:
  - generic and formulaic posts that say nothing specific
  - engagement-template structure
  - bot-like generic replies
  - an explicit instruction **not** to flag a post for simply being well written, using em-dashes, or being by a non-native speaker
- Feedback examples become category-specific: `rbf_examples = {rage:{pos,neg}, slop:{pos,neg}}`. Migrate the old `{pos,neg}` into `rage`.
- Cache entries store `{r, s, why, t}`. Treat old `{p}` entries as `{r:p, s:null}`; a null `s` means "needs re-ask only if slop is enabled".
- The extra output tokens are negligible, so there is no separate call.

### A5. Settings
New keys in `DEFAULTS`:

```js
slopEnabled: true,
slopThreshold: 0.65,
slopSites: { x:true, instagram:true, facebook:true, reddit:true, youtube:true, threads:true, bluesky:true, linkedin:true },
```

- **Options page:** a new "Slop filter" card with a toggle, a slider, and site checkboxes.
- **Popup:** a second small slider, or show both counts ("12 ragebait · 31 slop").
- **⊘ menu:** add "Hide as slop" next to "Hide as ragebait".
- **Stub:** "Not slop" or "Not ragebait", depending on which filter fired.

### A6. Test fixture and acceptance
Create `test/fixtures.json` with ≥ 40 labelled samples (`{text, site, isReply, label: "slop"|"rage"|"human"}`):
- **≥ 15 real-sounding human posts**, including some that **use em-dashes heavily**, German posts with spaced en-dashes, technical posts, news, and personal anecdotes.
- ≥ 12 slop posts: LinkedIn template, broetry, listicle with emoji bullets, "not X, it's Y".
- ≥ 8 bot replies, plus 4 genuine short replies ("Same here, the 2.3 release broke my build too").
- A few ragebait posts, to check the two scorers don't interfere with each other.

Add `test/run.js` (Node, no deps) that loads both scorers, prints a confusion table and lists every misclassified sample with its reasons.

**Acceptance:**
- **0 human posts hidden** at default thresholds.
- ≥ 80% of slop or bot samples caught by the local scorer alone.
- Existing ragebait behaviour is unchanged (re-run the v0.1 samples).

## 2. Feature B — Analytics ("Pi-hole for your feed")

### Goal
Show what was removed, how much, from where and why, and make it easy to spot and correct false positives. The model is the Pi-hole dashboard: a big headline number, a hidden share, charts over time, top lists, and a searchable query log.

**Everything stays local.** No telemetry, no server, unless the optional sync in B6 is turned on.

### B1. Event log
- **Storage: IndexedDB** (database `calmfeed`, store `events`), not `chrome.storage.local`. A log can outgrow storage quotas, and IndexedDB supports indexed queries.
- **Writes** go through the background worker. Content scripts send `{type:'logEvent', event}`.
- Each **event** records:

```ts
{
  id: string,            // uuid
  t: number,             // epoch ms
  site: string,          // 'x', 'linkedin', …
  filter: 'ragebait'|'slop'|'keyword'|'author'|'manual',
  source: 'heuristic'|'llm'|'user',
  score: number,         // score of the filter that fired
  scores: { r?: number, s?: number },
  reasons: string[],
  author: string,
  text: string,          // first 500 chars
  url: string|null,      // permalink if extractable, else page URL
  key: string,           // text hash, links to cache/feedback
  restored: boolean      // user clicked Show / Not slop / Not ragebait
}
```

- **Permalinks:** add an optional `permalink(el)` to each site adapter.
  - X: the `a[href*="/status/"]` inside the post.
  - Reddit: the `permalink` attribute.
  - LinkedIn: from `data-urn`.
  - YouTube: the `/watch?v=` link.
  - Otherwise `null`.
- **Dedup:** use the same `key` on the same site within 24 h. Then increment a `seenCount` on the existing event instead of adding a new one, since the same viral post shows up again and again.
- **Scanned counter:** keep a daily total of **posts scanned** per site and filter outcome, as a cheap aggregate in `chrome.storage.local` (`rbf_daily`, replacing `rbf_stats` with a migration). The "% hidden" figure needs this denominator.
- **Retention:** a setting with default 30 days, options 7 / 30 / 90 / forever, plus a max of 20,000 events. Prune on worker start-up and once a day.
- **Privacy switch:** "Store post text in log" (default on). When off, keep only metadata and reasons.

### B2. Dashboard page
New page `analytics.html`, opened from the popup ("Open dashboard") and linked from the options page.

- **Header tiles:**
  - Posts scanned (today / 7 d)
  - Hidden
  - % hidden
  - Split: ragebait / slop / lists
  - Time saved, estimated at ~6 s per hidden post. Label it as an estimate.
- **Chart 1:** hidden posts per hour (today) or per day (7 d / 30 d), stacked by filter.
- **Chart 2:** % hidden per site (horizontal bars).
- **Top lists:**
  - top filtered authors (with a one-click "Mute" or "Always allow")
  - top reasons ("em-dash ×", "stock phrase: here's the thing" and so on)
  - most re-seen posts
- **Query log:** a table of events, newest first. Columns: time, site, filter, score, author, text snippet, open-link icon.
  - Filters by site, filter type, source, date range and score range, plus full-text search.
  - Click a row to expand the full stored text and all reasons.
  - Row actions:
    - **Not slop / Not ragebait.** Marks the event `restored`, sends a feedback example, and overrides the cached verdict.
    - **Allow author.**
    - **Copy text.**
- **False-positive view:** a quick toggle that shows events near the threshold (score within ±0.1 of it), which are the likeliest mistakes.
- **Export:** CSV and JSON of the filtered log. Import is not needed.

**Constraints:**
- MV3 extension pages cannot load remote scripts. Draw the charts as hand-written inline SVG, or bundle a small library locally into `vendor/`.
- Keep it dependency-light, with no build step if possible.
- Follow the existing `ui.css` tokens, including light and dark mode.

### B3. Popup changes
- Today's counts split by filter.
- A sparkline of the last 7 days.
- An "Open dashboard" button.

### B4. Performance
- Logging must never block the hide path. `block()` hides first, then sends the log message.
- The background worker batches IndexedDB writes every ~1 s.
- The dashboard queries via indexes on `t`, `site` and `filter`, and paginates the log at 100 rows.

### B5. Acceptance
- Hidden posts appear in the dashboard within ~2 s.
- The dashboard loads in < 500 ms with 20k events.
- "Not slop" from the log changes future behaviour for the same text immediately.
- Retention pruning works.
- Export opens cleanly in Excel or Numbers.

### B6. Optional, later: self-hosted sync (do not build in v0.2)
Leave room for an endpoint URL setting. Each browser would POST batched events to a self-hosted server (e.g. a FastAPI + SQLite container), giving one dashboard across all devices and browsers, like Pi-hole's central admin page. For now, only keep the event schema stable and versioned (`schemaVersion: 1`) so this can be added later.
